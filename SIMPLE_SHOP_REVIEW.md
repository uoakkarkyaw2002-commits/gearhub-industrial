# Simple approved shops — 1.1.1

Seller: verified Google sign-in → enter shop name → Request a shop. No second OTP, custom URL, description, logo/contact/payment or plan wizard is required. Server allocates the URL, preserving optional old-client slug submissions and all existing applications. The previous uncommitted email-code wizard was never deployed; its files remain untouched in the original checkout and are not included here.

Owner: each pending card has Approve and secondary Reject. Approve is one request, in the existing immediate SQLite transaction. Repeating/concurrent approval returns success for the already approved application without inserting another shop or resetting its original trial. Legacy URL collisions are resolved during approval. Default plan50MiB/100active products and permissions stay unchanged. Trial starts at approval and ends two calendar months later in Myanmar time. Existing renewal, suspension and expiry/data-preservation controls remain.

All shops now use `public/index.html`, `style.css`, `desktop.css` and the same `store.js` used by root GearHub. An explicit tenant transport adapts tenant product/category/config/order data, rather than copying root business data or globally intercepting fetch. Shared layout/navigation, language/theme preferences, search/category filtering, sorting, product cards/gallery, cart drawer/quantity controls, checkout and manual receipt orders are reused. Seller management continues using the existing scoped platform dashboard for products/stock/orders/private receipts/settings. Root legacy admin is not given to sellers.

Tenant cart, retry and offline catalogue keys are namespaced; the old tenant cart key is preserved. Update drafts remain path-scoped; writes/files/in-progress checkout continue blocking updates. Root business/payment/catalogue is never a fallback for tenant requests. Browser storage display uses device estimates rather than exposing the root shop's storage statistics. Seller-only payment setup is required before checkout; incomplete bank fields do not display a usable payment method. New shops have no products/orders/payment details copied from GearHub. The empty catalogue points to adding a first product. Footer contacts use tenant settings and unset support-hours/verification/service promises are removed.

## Remaining release limits
Advanced visual redesign, auto billing/bank verification, native apps/push, category hierarchy editing and tenant-specific approved legal content are outside this change. Tenant API images are deliberately not cached by the shared worker; offline catalogue/cart support does not promise offline tenant image availability. The shared install manifest represents the platform PWA, not separately compiled seller apps. External account provisioning/payment/policy facts are not fabricated.

Review branch is separate; no production data changed during development. Rollback uses the previous reviewed code on the SAME durable path, or disables the platform flag on tenant-aware code; do not restore an old database/delete shops. No schema migration is required for this UI/URL allocation change. Before pilot rollout verify main CI/deployment, unchanged root catalogue and real seller/owner flow. Do not accept live customer payments without owner-verified payment/business/policy setup.
